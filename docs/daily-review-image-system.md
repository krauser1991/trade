## 一、目标

后续每日复盘不再默认生成 PDF，而是生成适合手机阅读和转发的深色信息图风格 HTML，并在需要时从 HTML 截取竖版长图 PNG。

系统目标：

- 让每日复盘具备固定结构，避免临场散文化；
- 将行情、题材、持仓、交易行为和次日计划统一到同一套数据口径；
- 保留 Markdown 原文，方便 Obsidian 沉淀；
- 用 HTML 承载视觉表达，用 PNG 作为最终分享图；
- 保持数据来源可追溯，策略判断可复盘。

## 二、输出物

每日复盘默认生成三类正式文件：

| 类型 | 路径 | 用途 |
|---|---|---|
| Markdown | `daily-reviews/YYYY-MM-DD-主题.md` | 正文沉淀、Obsidian 阅读、长期复盘 |
| HTML | `output/html/YYYY-MM-DD-主题.html` | 视觉化页面、可二次打开检查 |
| PNG 长图 | `output/images/YYYY-MM-DD-主题.png` | 手机阅读、转发、归档 |

辅助数据文件：

| 类型 | 路径 | 用途 |
|---|---|---|
| 每日数据 JSON | `data/daily/YYYY-MM-DD-market.json` | 行情、账户、题材、策略判断的结构化输入 |
| 渲染模板 | `templates/daily-review-dark.html` | 深色信息图 HTML 模板 |
| 渲染脚本 | `scripts/render_daily_review.py` | JSON/Markdown 到 HTML 的转换 |
| 截图脚本 | `scripts/screenshot_daily_review.js` | HTML 到 PNG 长图的截图 |

PDF 仅在用户明确要求时生成，不作为每日复盘默认交付物。

## 三、数据渠道

数据渠道按可靠性和自动化程度分为三层。

### 1. 人工确认数据

这些数据必须由用户提供或人工确认，不能由行情接口替代：

| 数据 | 来源 | 说明 |
|---|---|---|
| 总资产 | 券商截图或手动填写 | 记录账户真实状态 |
| 当日盈亏 | 券商截图或手动填写 | 区分账户盈亏与单票盈亏 |
| 当前持仓 | 券商截图、持仓 CSV、手动填写 | 包含仓位、成本、浮盈亏 |
| 当日成交 | 交割单、成交截图、手动填写 | 用于判断是否按计划执行 |
| 盘中行为 | 用户描述 | 包含追高、恐慌、卖飞、随手单等行为标签 |

### 2. 半自动行情数据

这些数据可以从同花顺、东方财富、财联社、交易软件导出或公开行情接口补充，但生成前需要核对日期和口径：

| 数据 | 说明 |
|---|---|
| 指数涨跌 | 上证、深成指、创业板、科创、北证等 |
| 成交额 | 两市成交额、较前日增减 |
| 涨跌家数 | 上涨、下跌、平盘家数 |
| 涨停跌停 | 涨停数、跌停数、炸板率、封板率 |
| 连板高度 | 最高板、连板梯队 |
| 板块表现 | 涨幅榜、跌幅榜、成交额榜 |
| 个股表现 | 核心股涨跌幅、成交额、是否涨停/炸板/断板 |

### 3. 策略分析数据

这些数据不能只依赖接口，需要结合交易体系判断：

| 数据 | 判断方式 |
|---|---|
| 市场状态 | 指数、成交额、涨跌家数、赚钱效应综合判断 |
| 情绪周期 | 连板高度、炸板率、跌停反馈、高标承接综合判断 |
| 主线题材 | 涨幅、成交额、前排强度、持续性和消息催化共同确认 |
| 核心锚点 | 题材地位、容量、辨识度、资金承接共同确认 |
| 明日策略 | 市场状态、持仓风险、题材持续性、账户状态共同决定 |

## 四、结构化数据模型

每日复盘数据文件使用 JSON，推荐包含以下顶层字段：

```json
{
  "date": "YYYY-MM-DD",
  "title": "今日复盘与明日策略",
  "market": {},
  "breadth": {},
  "themes": [],
  "stocks": [],
  "account": {},
  "trades": [],
  "holdings": [],
  "review": {},
  "next_day_plan": {},
  "risk_notice": "仅作个人复盘与交易计划，不构成投资建议。"
}
```

关键字段要求：

| 字段 | 必填 | 说明 |
|---|---|---|
| `date` | 是 | 交易日期 |
| `market` | 是 | 指数、成交额、市场状态 |
| `breadth` | 是 | 涨跌家数、涨停跌停、连板高度 |
| `themes` | 是 | 主线题材、分支题材、持续性判断 |
| `stocks` | 是 | 核心股、前排股、中军、风险股 |
| `account` | 否 | 总资产、盈亏、仓位 |
| `trades` | 否 | 当日真实成交 |
| `holdings` | 否 | 当前持仓和处理计划 |
| `review` | 是 | 今日结论、纪律问题、归因 |
| `next_day_plan` | 是 | 明日策略、买卖条件、风控线 |

如果账户或成交数据缺失，必须在复盘中明确标记“未提供”，不能猜测。

## 五、复盘策略判断口径

每日复盘必须先判断市场，再判断题材，最后判断个人操作。

### 1. 市场状态

市场状态分为：

| 状态 | 判定特征 |
|---|---|
| 强势主升 | 指数放量上涨，赚钱效应集中，核心题材持续加强 |
| 震荡轮动 | 指数无明显方向，题材快速切换，持续性一般 |
| 弱修复 | 指数反弹但成交不足，高标或核心承接不稳 |
| 退潮 | 跌停增加、炸板率高、高标负反馈明显 |
| 冰点 | 亏钱效应极强，但可能孕育次日修复 |
| 混沌 | 指数、题材、情绪互相背离，难以形成主攻方向 |

### 2. 主线题材

题材分为：

| 类型 | 操作含义 |
|---|---|
| 主线加强 | 可以围绕核心股和前排做计划 |
| 主线分歧 | 只看最强承接，不追后排 |
| 主线退潮 | 降仓或退出，避免补跌 |
| 新题材试错 | 小仓观察，等资金确认 |
| 支线轮动 | 只适合轻仓快进快出 |

### 3. 持仓处理

每只持仓必须给出明确动作：

| 动作 | 含义 |
|---|---|
| 留 | 趋势、题材、盘口仍支持持有 |
| 减 | 逻辑未坏但仓位或节奏需要下降 |
| 清 | 逻辑破坏、走势破位或违反买入前提 |
| 加 | 只有在主线加强且账户风险允许时使用 |
| 做 T | 仅对熟悉持仓，且有明确日内区间时使用 |
| 观察 | 不新增仓位，只等待验证 |

### 4. 纪律复盘

每日必须至少复盘一个行为问题：

- 是否随手单；
- 是否追高；
- 是否卖飞后乱买；
- 是否低位割肉；
- 是否违反仓位上限；
- 是否把题材逻辑当成买入信号；
- 是否没有提前写退出条件。

## 六、HTML 与长图生成流程

标准流程：

```text
用户输入/行情数据
        ↓
data/daily/YYYY-MM-DD-market.json
        ↓
daily-reviews/YYYY-MM-DD-主题.md
        ↓
templates/daily-review-dark.html
        ↓
output/html/YYYY-MM-DD-主题.html
        ↓
Playwright 截完整页面
        ↓
output/images/YYYY-MM-DD-主题.png
```

生成规则：

- Markdown 负责完整文字沉淀；
- JSON 负责结构化字段和视觉组件数据；
- HTML 负责排版、颜色、表格和卡片；
- PNG 必须从 HTML 截图生成，不能手工拼图；
- HTML 和 PNG 必须与 Markdown 内容一致，不能出现结论冲突。

第一阶段本地命令：

```bash
python3 scripts/render_daily_review.py data/daily/sample-market.json
node scripts/verify_daily_review_html.js output/html/2026-08-11-今日复盘与明日策略.html
node scripts/screenshot_daily_review.js output/html/2026-08-11-今日复盘与明日策略.html
```

正式每日复盘时，将 `sample-market.json` 替换为当天的 `data/daily/YYYY-MM-DD-market.json`。

第一阶段边界：

- 行情、题材、账户和成交数据先以人工确认或半自动整理为准；
- 系统负责校验、渲染、视觉输出和截图；
- 自动行情抓取、公告抓取和策略自动初判属于第二、三阶段能力。

## 七、视觉规范

整体风格参考用户提供的两张深色长图。

### 1. 页面尺寸

| 场景 | 建议宽度 | 说明 |
|---|---:|---|
| 长图主宽度 | 760px-900px | 适合手机缩放阅读 |
| 手机预览 | 390px-430px | 验证小屏不溢出 |
| 桌面预览 | 1080px-1280px | 验证居中和留白 |

### 2. 页面结构

页面从上到下依次为：

1. 顶部标题区；
2. 关键指标卡片；
3. 今日一句话结论；
4. 指数与情绪复盘；
5. 主线题材与核心股；
6. 持仓与操作复盘；
7. 明日策略；
8. 风险条件；
9. 纪律口令；
10. 免责声明。

### 3. 颜色规范

| 用途 | 颜色倾向 |
|---|---|
| 背景 | 深蓝黑、墨色 |
| 卡片 | 深灰蓝 |
| 上涨/积极 | 红色 |
| 下跌/风险 | 绿色 |
| 中性文字 | 浅灰 |
| 强调线 | 蓝、紫、金少量使用 |

A 股语境中，红色表示上涨，绿色表示下跌。不得反用。

## 八、验收清单

每次生成 HTML/PNG 后必须检查：

- HTML 文件存在；
- PNG 文件存在；
- 页面标题、日期正确；
- 目录或分区完整；
- 指数、成交额、涨跌家数、涨停跌停数据有来源或明确标记缺失；
- 持仓和成交数据缺失时明确写“未提供”；
- 表格不重叠；
- 长股票名、长题材名能换行；
- 手机宽度不出现横向溢出；
- PNG 是完整长图，不是首屏截图；
- 底部包含“仅作个人复盘与交易计划，不构成投资建议”；
- 最终回复列出 Markdown、HTML、PNG 路径。

## 九、实施优先级

### 第一阶段：规则与模板

- 建立本文档；
- 建立每日 JSON 数据模板；
- 建立深色 HTML 模板；
- 建立 HTML 渲染脚本；
- 建立 Playwright 长图截图脚本。

### 第二阶段：半自动数据接入

- 接入或半自动整理指数、成交额、涨跌家数；
- 接入涨停、跌停、连板高度；
- 接入题材和核心股列表；
- 将账户数据保持为人工确认。

### 第三阶段：策略辅助

- 自动生成市场状态初判；
- 自动生成题材强弱分层；
- 自动生成持仓处理候选建议；
- 自动生成次日执行清单草稿；
- 人工最终确认策略结论。

## 十、风险与边界

本系统用于个人复盘和交易训练，不做自动交易，不直接给出无条件买卖指令。

必须遵守：

- 数据日期必须明确；
- 不确定数据必须标记来源或缺失；
- 策略判断必须说明触发条件；
- 账户数据必须以用户提供为准；
- 任何输出都必须保留风险提示；
- 不因视觉效果牺牲复盘准确性。

一句话原则：

```text
先保证数据真实和策略口径稳定，再追求长图好看。
```
